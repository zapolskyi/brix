# BRIX 22° — технічне завдання

Джерело: `design-source/brix22-tz.html`, частина III. Тут — робоча версія,
доповнена рішеннями, ухваленими на старті розробки (позначені 📌).

---

## Мета проєкту

Показати повний цикл WooCommerce-розробки: власну тему з нуля, бізнес-логіку
в окремому плагіні, кастомізацію каталогу і checkout, інтеграції з доставкою
та оплатою, продуктивність і чистий код у Git.

**Жодної готової теми чи page builder'а** — саме це відрізняє кейс розробника
від кейсу «зібрав сайт».

## Стек

| Шар | Рішення | Навіщо в портфоліо |
|---|---|---|
| Платформа | WordPress 7.1, WooCommerce, PHP 8.2+ | сумісність з HPOS і блочним checkout |
| Тема | власна `brix`: PHP-шаблони + override шаблонів Woo, SCSS | верстка і розуміння template hierarchy |
| Логіка | плагін `brix-core`, Composer, PSR-4, ООП | розділення презентації та бізнес-логіки |
| Фронтенд JS | ванільний JS, WooCommerce Store API / REST | швидкий AJAX без jQuery-залежностей |
| Контент | Gutenberg + власні блоки (hero, паспорт лоту, гайд), Secure Custom Fields | клієнт редагує сторінки сам |
| Середовище | Local, Git (GitHub), staging, GitHub Actions | професійний робочий процес |

📌 **Збірка — `sass` CLI, не Vite.** ТЗ називало Vite, але на TORQ перевірено
простіший підхід: `npm run css` компілює SCSS, зібраний CSS комітиться в репо,
тема працює на хостингу без жодної збірки. JS — ванільні файли без бандлера.
Причина в `DECISIONS.md`.

📌 **Один репозиторій над `wp-content/`**, який тримає і тему, і плагін.
Одне посилання на GitHub для портфоліо замість двох.

📌 **Кастомні поля — Secure Custom Fields, не власний метабокс.** ТЗ
допускало обидва варіанти. Пояснення — в `DECISIONS.md`.

## Функціональні модулі

Пріоритети: **MVP** — без цього магазин не працює · **Should** — робить кейс
повним · **Wow** — те, що запам'ятають.

### A. Каталог і товари

| Пр. | Що | Деталі |
|---|---|---|
| MVP | Варіативні товари: вага (100 / 250 г / 1 кг) × помел (зерно, еспресо, фільтр, френч-прес, турка) | ціни й залишки на рівні варіацій, зрозумілий селектор замість стандартних dropdown'ів |
| MVP | Паспорт лоту: кастомні мета-поля + таксономії «Країна», «Обробка», «Смакові ноти» | 📌 поля на Secure Custom Fields, групи реєструються кодом у `brix-core`; вивід у картці, каталозі та schema |
| Should | Шкали смаку та індикатор свіжості від дати обжарки | |
| Should | Дегустаційні набори (bundle / grouped) і подарункові сертифікати | |
| Wow | CPT «Виробники» з двостороннім зв'язком «ферма ↔ лоти» і картою регіону | |

### B. Пошук і фільтри

| Пр. | Що | Деталі |
|---|---|---|
| MVP | AJAX-фільтри без перезавантаження: країна, обробка, ноти, обжарка, ціна | власна реалізація, стан у URL (можна поділитись посиланням), коректні canonical для SEO |
| Should | Живий пошук з підказками товарів і гайдів | |

### C. Квіз «Підібрати каву»

| Пр. | Що | Деталі |
|---|---|---|
| Wow | 5–6 питань (як заварюєте, молоко чи ні, улюблені смаки) → 2–3 рекомендовані лоти з уже обраним помелом | кнопки «Додати в кошик» і «Оформити підписку», результат зберігається в кабінеті; логіка через REST-ендпоінт плагіна |

### D. Підписка BRIX Club

| Пр. | Що | Деталі |
|---|---|---|
| Should | «Кожні 2 або 4 тижні» зі знижкою 10% — перемикач прямо в картці товару | власна спрощена реалізація; пауза, пропуск і зміна лоту в кабінеті |

### E. Кошик і checkout

| Пр. | Що | Деталі |
|---|---|---|
| MVP | Блочний Cart і Checkout, адаптований під бренд, мінімум полів | |
| MVP | Оплата: Stripe (Apple Pay / Google Pay) для ЄС, LiqPay або monobank для України | тестовий режим |
| Should | Прогрес-бар до безкоштовної доставки і upsell дріп-пакетів або фільтрів | |
| Should | Нагадування «Перевірте помел» для еспресо-лотів, обраних під фільтр | |

### F. Доставка

| Пр. | Що | Деталі |
|---|---|---|
| MVP | Нова Пошта: автокомпліт міста й відділення/поштомату через API | власна інтеграція краще за готовий плагін |
| MVP | Міжнародна зона ЄС, безкоштовна доставка від суми, самовивіз з обжарювальні | |

### G. B2B для кав'ярень

| Пр. | Що | Деталі |
|---|---|---|
| Wow | Форма заявки → модерація в адмінці → роль «Wholesale» | оптові ціни, мінімальне замовлення 5 кг, швидка форма замовлення таблицею, оплата за рахунком |

### H. Кабінет, контент, листи

| Пр. | Що |
|---|---|
| Should | «Повторити замовлення» в один клік, збережені результати квізу |
| Should | Гайди заварювання (CPT): кроки, пропорції, вбудований таймер |
| Should | Мультимовність UA/EN і валюти UAH/EUR |
| Should | Брендовані транзакційні листи WooCommerce |
| Wow | Лист «Кава закінчується?» через 3 тижні після покупки з кнопкою повтору (Action Scheduler) |
| Wow | Сторінка «Прозорість»: таблиця лотів з ціною фермеру, що генерується з даних товарів |

## Якість, швидкість, безпека

| Метрика | Ціль |
|---|---|
| LCP на мобільному | < 2.5 с |
| CLS | < 0.1 |
| INP | < 200 мс |
| Lighthouse, усі категорії | 90+ |

**Продуктивність:** WebP/AVIF, адаптивні зображення, критичний CSS, скрипти
лише там, де потрібні, вимкнені зайві стилі та скрипти Woo на некомерційних
сторінках, об'єктний кеш.

**SEO:** Product schema з Offer і AggregateRating, breadcrumbs, чисті URL
фільтрів, Open Graph для товарів.

**Доступність:** WCAG 2.2 AA, клавіатурна навігація у фільтрах, селекторі
варіацій і квізі.

**Безпека:** nonce, санітизація та екранування, перевірка capabilities,
жодних платіжних даних на сервері.

**Аналітика:** GA4 ecommerce-події — `view_item`, `add_to_cart`,
`begin_checkout`, `purchase`.

**Код:** WordPress Coding Standards (PHPCS), сумісність з HPOS, лінт і збірка
в GitHub Actions, e2e-тест покупки на Playwright.

## Оформлення кейсу

- **Чесна подача:** «концепт-бренд, спроєктований і розроблений мною від ідеї
  до деплою». Клієнти цінують це більше, ніж вигаданого замовника.
- **Структура сторінки кейсу:** задача → рішення → 4–5 ключових фіч з GIF →
  метрики Lighthouse → стек → посилання на демо і GitHub.
- **Відео на 60–90 секунд:** квіз → картка лоту → фільтри → checkout
  з Новою Поштою → лист-підтвердження.
- **Код на GitHub:** README з архітектурою, скріншотами й інструкцією запуску —
  його реально відкривають технічні клієнти.
- **Демо-доступ:** тестові картки Stripe і тестовий B2B-акаунт,
  щоб будь-хто пройшов покупку сам.
