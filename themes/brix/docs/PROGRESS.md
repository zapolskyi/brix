## Зроблено

### Аналіз і документація

Прочитано й розібрано вхідні матеріали з `design-source/`: ТЗ на 3 частини
(аналіз ніші, бренд, технічне завдання) і 21 артборд.

ТЗ перенесено в markdown і закомічено, бо самі макети в репозиторій не йдуть:
`01-brend-i-analiz.md`, `02-tehnichne-zavdannya.md`, `03-makety.md`.

### Репозиторій

Git над `wp-content/`, гілка `main`. `.gitignore` пропускає все, крім
`themes/brix/` і `plugins/brix-core/` — один репозиторій тримає і тему,
і плагін, одне посилання для портфоліо.

Макети лежать локально в `themes/brix/docs/design-source/` і навмисно
не входять у репозиторій: це робочі файли редактора, а не частина теми.

### Фаза 0 — фундамент

**WordPress 7.1 · PHP 8.2 · WooCommerce 11.1 · HPOS увімкнено.**

Налаштування магазину застосовані через wp-cli (у tools/ ще не зафіксовані —
це задача 2.8, поки перелік тут):

- локаль `uk`, часовий пояс Europe/Kyiv, дати `d.m.Y`, пермалінки `/%postname%/`
- склад: Київ, `UA:UA-30`; валюта UAH, символ праворуч, роздільник тисяч — пробіл,
  без копійок; кг і см
- зони продажу: Україна + 27 країн ЄС; гостьовий checkout увімкнено
- облік залишків увімкнено, поріг низького залишку — 5
- майстер онбордингу пропущено, маркетингові підказки й телеметрія вимкнені
- створено 8 контентних сторінок (`/about/`, `/contacts/`, `/delivery/`, `/faq/`,
  `/transparency/`, `/wholesale/`, `/club/`, `/quiz/`) і 5 категорій товарів
  (Core, Origin, Lab, Drip & Try, Gear)
- 5 меню: головне + чотири колонки підвалу
- прибрано демо-контент WordPress (Sample Page, Hello world, коментар)
- у `wp-config.php` увімкнено `WP_DEBUG` з логом у файл, без виводу у верстку

**Тема `brix`.** `functions.php` лише підключає модулі з `inc/`: `setup`,
`enqueue`, `helpers`, `template-tags`, `class-brix-plain-walker` і
`woocommerce` — останній вантажиться тільки за наявності плагіна.
Шаблони: `index`, `page`, `single`, `404`, `header`, `footer`, дві частини
контенту. Шапка зі стікі-позицією, мобільним меню й лічильником кошика;
підвал з підпискою, трьома колонками меню та правовим рядком.

**Стилі.** Токени з макетів — кастомними властивостями в
`abstracts/_tokens.scss`. База (скидання, типографіка, доступність),
розкладка, шапка, підвал, кнопка. Збірка `sass` CLI: `npm run css`,
`npm run build`, `npm run zip`. Скомпільований CSS комітиться.

**Шрифти.** 16 локальних `woff2` — по дві підмножини (cyrillic + latin)
на накреслення, 385 КБ разом. Перегенерація: `npm run fonts`.
Дві кириличні підмножини йдуть у `preload`.

**Плагін `brix-core`.** Composer + PSR-4, `Plugin::boot()` створює модулі
зі списку й викликає `register()`. Оголошено сумісність з HPOS і блочним
checkout. Без WooCommerce плагін не падає, а пише в адмінку.

**Якість.** PHPCS з WordPress Coding Standards на тему й плагін — чисто,
18 файлів. Сторінки `/`, `/shop/`, `/cart/`, `/account/` віддають 200,
неіснуючі — 404, `debug.log` порожній при `WP_DEBUG = true`.

## Наступний крок

Починаємо **фазу 1 — дизайн-система**. Токени вже перенесені, далі:

1. Повний набір компонентів у `assets/scss/components/`: чипи, сегмент-контрол,
   теги обробки, поля форм
2. `.brix-pack` — пачка кави на CSS з container queries, 7 варіантів обробки
3. `.brix-card`, `.brix-dgrid`, `.brix-brix` (шкала °Bx), `.brix-bars`, `.brix-fresh`
4. Шаблон сторінки UI-кіту для візуальної звірки з `design-source/preview/ui-kit.html`
5. Довести шапку й підвал до макета в деталях

Критерій закриття фази: UI-кіт у темі збігається з макетом, пачка коректно
масштабується від 120 до 520 px, клавіатурна навігація видима всюди,
мобільна шапка працює на 390 px без горизонтального скролу.

## Журнал

### 16 вересня 2026 — фаза 0 закрита

Розібрано ТЗ і всі 21 артборд. Ухвалено стартові рішення: один репозиторій
над `wp-content`, збірка на `sass` CLI замість Vite, макети поза
репозиторієм. Створено документацію, заведено git.

Далі за один заход пройдено всю фазу 0: WooCommerce з HPOS і налаштуваннями
під Україну, каркас теми з шаблонами й токенами, каркас плагіна на PSR-4,
збірка SCSS, 16 локальних шрифтів, PHPCS.

Дві помилки, знайдені й виправлені по дорозі:

- **`npm run zip` збирав порожній архів.** `git archive` із підтеки додає
  до фільтра шлях поточного каталогу, тож під `HEAD:themes/brix` не
  підпадав жоден файл. Заразом виявилось, що `export-ignore` з кореневого
  `.gitattributes` на архівоване піддерево не діє — docs і scss усе одно
  поїхали б на хостинг. Тепер у теми свій `.gitattributes`.
- **Walker меню екранував заголовки вдруге.** Назви пунктів WordPress
  зберігає вже як HTML (`&amp;`, `&#8217;`), тож `esc_html()` показував
  би сутності у верстці. Виправлено як у ядрі: фільтр `the_title`
  і `wp_kses_post`.

Наступна сесія — фаза 1, дизайн-система.
