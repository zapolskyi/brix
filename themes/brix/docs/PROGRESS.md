## Зроблено

### Аналіз і документація

Прочитано й розібрано вхідні матеріали з `design-source/`: ТЗ на 3 частини
(аналіз ніші, бренд, технічне завдання) і 21 артборд.

ТЗ перенесено в markdown і закомічено, бо самі макети в репозиторій не йдуть:

- `01-brend-i-analiz.md` — ніша, конкуренти, аудиторія, бренд, айдентика, паспорт лоту
- `02-tehnichne-zavdannya.md` — стек, структура сайту, 8 функціональних модулів з пріоритетами, вимоги до якості, архітектура репо
- `03-makety.md` — карта 21 екрана, токени, інвентар компонентів і те, що врахувати при верстці

### Репозиторій

Git над `wp-content/`, гілка `main`. `.gitignore` пропускає все, крім
`themes/brix/` і `plugins/brix-core/` — один репозиторій тримає і тему,
і плагін, одне посилання для портфоліо.

Макети лежать локально в `themes/brix/docs/design-source/` і навмисно
не входять у репозиторій: це робочі файли редактора, а не частина теми.

## Наступний крок

Дороблюємо **фазу 0**:

1. Встановити й налаштувати WooCommerce, увімкнути HPOS
2. Каркас теми: `style.css`, `functions.php`, `inc/setup.php`, `inc/enqueue.php`, базові шаблони
3. `package.json` зі скриптами `css` / `build` / `zip`, підключений `sass`
4. Локальні шрифти `woff2` з підмножинами cyrillic/latin
5. Каркас плагіна `brix-core` з PSR-4 автозавантаженням

Критерій закриття фази: тема активується без жодного notice при `WP_DEBUG = true`,
`/` віддає 200 із шапкою й підвалом за макетом, `npm run build` збирає CSS.
