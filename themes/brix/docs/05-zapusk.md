# Запуск на хостингу

Покрокова інструкція для власника: що взяти, куди покласти й що
перевірити. Розрахована на Hostinger, але відрізнятиметься хіба
назвами кнопок.

---

## Крок 1. Що дістати заздалегідь

Три речі. Дві безкоштовні, третя — теж.

### Нова Пошта — ✅ вже зроблено

Довідник **уже вивантажений** на локальній машині: 11 210 міст і
52 350 точок видачі. Автокомпліт у checkout працює.

Ключ більше не потрібен — ні тут, ні на хостингу. Він лежить у
локальному `wp-config.php` лише для повторної синхронізації, і на
сервер не переноситься.

Тобі лишається тільки **перенести таблицю** — це крок 3.4.

> Якщо колись захочеш оновити довідник: `wp brix np-sync --fresh`.
> Займає близько десяти хвилин.

### Ключі LiqPay

`liqpay.ua` → увійти → **Налаштування** → **Ключі API**. Там дві пари:
тестова (`sandbox_...`) і бойова. **Для демо беремо тестову** — вона
приймає платежі, але грошей не списує.

Потрібні обидва рядки пари: публічний і приватний ключ.

✅ **Тестові ключі вже є** і вписані на локальному сайті. В архів
`.wpress` вони потрапляють разом із базою; вписувати їх ще раз
(крок 4) треба лише на запасному шляху.

### Токен monobank *(за бажанням)*

`api.monobank.ua` → розділ еквайрингу → тестовий токен. Потрібен, лише
якщо хочеш показати два способи оплати. Без нього monobank просто не
зʼявиться в checkout — нічого не зламається.

## Крок 2. Архів для All-in-One WP Migration

Сайт переїжджає одним файлом `.wpress`: база, фото, переклади й
таблиця Нової Пошти всередині. SSH для цього не потрібен.

**Файл збирається з чистої копії, а не з робочого локального сайту.**
На робочому — тестові замовлення, особисті облікові записи, `.git`,
`node_modules` і `dist/`: All-in-One забирає весь `wp-content`, і
все це опинилося б на сервері, частина — доступна за прямою адресою.

Чиста копія — те саме, що генеральна репетиція:

1. Свіжий WordPress з окремою базою, WooCommerce і Secure Custom Fields.
2. Архіви з `npm run zip` (тема й плагін, тека `wp-content/dist/`).
3. `wp brix setup`, `wp brix demo`, `wp brix translate`.
4. Таблиця `wp_brix_np_places` з локальної бази (див. 3.4).
5. Налаштування LiqPay (тестові ключі) з локальної бази.
6. Адміністратор — окремий, із сильним паролем.
7. All-in-One WP Migration → **Експорт → Файл**.

Готовий файл: `wp-content/dist/brix-hostinger.wpress` (≈155 МБ, у git
не потрапляє). Перевірено: ключа Brevo, особистих адрес і тестових
замовлень у ньому немає.

## Крок 3. Hostinger

### 3.1. Імпорт

1. Сайт на Hostinger уже є: `brix.zapolskyi.com`. SSL (Let's Encrypt)
   має бути ввімкнений у hPanel.
2. **Онови WordPress до останньої версії** й перевір PHP 8.2+ (hPanel →
   Додатково → Конфігурація PHP). Архів зібрано на WordPress 7.1 —
   старіше ядро з новішою базою працює погано.
3. Плагіни → Додати → **All-in-One WP Migration** → активувати.
4. All-in-One WP Migration → **Імпорт** → перетягни
   `brix-hostinger.wpress` → **Продовжити**.
5. Після імпорту All-in-One попросить двічі зберегти **Налаштування →
   Постійні посилання**. Зроби це — інакше сторінки віддадуть 404.

> **Файл не вантажиться через ліміт.** Або підніми ліміт у hPanel →
> Конфігурація PHP → `upload_max_filesize` і `post_max_size` до 256M,
> або поклади файл через Файловий менеджер у
> `wp-content/ai1wm-backups/` і віднови його зі сторінки
> All-in-One → **Резервні копії**.

**Імпорт замінює все**, разом із користувачами: адміністратор тепер той,
що в архіві (логін і пароль — окремо, не в цьому файлі). Одразу після
входу **зміни пароль**. Плагіни Hostinger після імпорту вимкнені — з
них потрібен лише LiteSpeed Cache (3.7).

LiqPay уже налаштований тестовими ключами, довідник Нової Пошти —
на місці.

Сайт закритий від пошукових систем (Налаштування → Читання). Для
портфоліо так і лишаємо: показуємо за посиланням, а вигаданий магазин
у пошуку лише вводив би людей в оману.

### 3.2. Запасний шлях: з нуля по SSH

Якщо All-in-One не підходить — сайт збирається на сервері тими ж
командами, що й чиста копія.

1. Постав і активуй WooCommerce і Secure Custom Fields, завантаж
   `brix.zip` (Вигляд → Теми → Додати) і `brix-core.zip` (Плагіни →
   Додати → Завантажити), активуй обидва.
2. По SSH, з кореня сайту:

```bash
wp brix setup      # мова, валюта, сторінки, меню, зони доставки, оплата
wp brix demo       # 14 лотів, 90 варіацій, 4 виробники, 5 гайдів, фото
wp brix translate  # англійські тексти для /en/
```

3. Перенеси довідник Нової Пошти (3.4) і впиши ключі LiqPay (крок 4).

Усі три команди безпечно запускати повторно — нічого не подвоюється.
`wp brix translate` **мовчки пропускає** переклади, які вже є, і все
одно пише «Success»; щоб перезаписати їх файлом з репозиторію, додай
`--force`.

### 3.3. Що робить setup

Крім очевидного — і чому без цього сайт на хостингу вийшов би не
таким, як локально (усе знайдено генеральною репетицією на чистому
WordPress):

- ставить **класичні** кошик і checkout замість блокових, які створює
  свіжий WooCommerce. На блоках не працювали б Нова Пошта, спосіб
  отримання, картки оплати й покупка без JavaScript;
- ставить українські мовні пакети **до** того, як вмикає українську:
  інакше WordPress мовчки лишає сайт англійським;
- називає сторінки магазину українською, кабінету дає адресу
  `/account/`, публікує політику конфіденційності й умови продажу,
  ховає англійські заглушки WordPress і WooCommerce;
- вимикає «атрибуцію замовлень» WooCommerce — маркетингові cookies
  без згоди.

Тексти сторінок кладе `wp brix demo` — лише в порожні сторінки.

> **Курс євро.** Ціни в євро рахуються з гривні за курсом у
> WooCommerce → Налаштування → Загальні → «Друга валюта: євро».
> За замовчуванням 48 ₴ за євро. Валюту покупець перемикає знаком
> «₴ / €» у шапці; англійська версія без вибору показує євро. Нуль
> вимикає євро зовсім.

### 3.4. Довідник Нової Пошти

У `.wpress` він уже є. На запасному шляху таблицю `wp_brix_np_places`
з локальної бази треба перенести вручну:

```bash
# локально
wp db export np.sql --tables=wp_brix_np_places

# на хостингу, завантаживши файл
wp db import np.sql
```

Дамп від `wp db export` сам видаляє й перестворює таблицю — тому
цей шлях працює.

Через phpMyAdmin — обережно. Плагін при активації вже створив цю
таблицю, порожню, і з колонками в іншому порядку, ніж локальна.
Звичайний експорт phpMyAdmin таблицю не видаляє, тож імпорт упаде на
«table already exists», а вставка лише даних розкладе їх не по тих
колонках. При експорті постав галочку **«Add DROP TABLE»**.

Перевірка після імпорту: `wp db query "SELECT COUNT(*) FROM wp_brix_np_places"`
має показати 63 560.

### 3.5. Справжній cron

**Це критично, і про це легко забути.** WP-Cron спрацьовує від
відвідувачів. На демо-стенді, куди ніхто не заходить, підписки BRIX
Club не поновляться ніколи, а нагадування «Кава закінчується?» не піде.

У `wp-config.php` додай:

```php
define( 'DISABLE_WP_CRON', true );
```

hPanel → **Додатково → Cron-завдання** → нове завдання, раз на 15 хвилин:

```
wget -q -O - https://ТВІЙ-ДОМЕН/wp-cron.php?doing_wp_cron >/dev/null 2>&1
```

### 3.6. Пошта

Листи з шаред-хостингу масово летять у спам, а лист-підтвердження, який
не дійшов, ламає всю демонстрацію покупки.

Пошту сайту відправляє **Brevo** — модуль `Mail\Brevo` у brix-core.
SMTP-плагін не потрібен. У `wp-config.php` на хостингу додай два
рядки (ключ — той самий, що локально, він лежить у локальному
`wp-config.php`):

```php
define( 'BRIX_BREVO_KEY', 'xkeysib-…' );
define( 'BRIX_BREVO_SENDER', 'sender@example.com' );
```

Перевір по SSH:

```bash
wp brix mail-test sender@example.com
```

Без SSH — оформи тестове замовлення на свою пошту: лист має прийти
від «BRIX 22°», а в Brevo → Transactional → Logs — статус delivered.

Туди ж, у `wp-config.php`, — справжній cron (3.5):
`define( 'DISABLE_WP_CRON', true );`. Редактор файлів в адмінці
вимикає сам плагін, окремо прописувати `DISALLOW_FILE_EDIT` не треба.

Що варто знати:

- **Ліміт — 300 листів на добу**, і він спільний з TORQ і Площиною:
  акаунт Brevo один. Для демо з запасом.
- Відправник — адреса, підтверджена в Brevo. З адресою на Gmail
  Brevo шле від `…@brevosend.com` — так листи не ріжуться захистом
  Gmail від підробки. Ім'я відправника — «BRIX 22°», відповіді
  приходять на твою пошту. Для бойового магазину — власний домен із
  записами SPF і DKIM від Brevo.
- Листи на тестові домени (`example.com`, `.local`, `.test`) повз
  Brevo: вони не приймають пошти, а відмови псують репутацію
  відправника. Це демо-акаунти `demo@brix.local` і `b2b@brix.local`.
- Якщо Brevo не відповів, лист піде поштою хостингу, а збій запишеться
  в WooCommerce → Стан → Журнали, джерело `brix-brevo`.

### 3.7. Кеш

У Hostinger зазвичай LiteSpeed. Постав **LiteSpeed Cache**, увімкни
сторінковий і обʼєктний кеш. Нічого налаштовувати глибше не треба.

## Крок 4. Ключі платіжок

Адмінка → **WooCommerce → Налаштування → Платежі**.

Після імпорту `.wpress` LiqPay уже налаштований тестовими ключами —
цей крок лише для запасного шляху.

**LiqPay** → налаштувати:
- Публічний ключ і приватний ключ із кабінету
- **Тестовий режим — увімкнений**
- Увімкнути спосіб оплати

**monobank** (якщо брав токен) → те саме, поле «Токен продавця».

> Якщо вмикаєш обидва — дай їм різні назви. Два однакові «Картка
> онлайн» у checkout виглядають як помилка сайту. За замовчуванням
> monobank підписаний «Картка · Apple Pay · Google Pay».

> Без ключів спосіб оплати не показується покупцям — це зроблено
> навмисно, щоб ніхто не обрав оплату, яка гарантовано впаде.

**Оплата при отриманні** вже ввімкнена. Поріг суми, вище якого вона
зникає, — у її ж налаштуваннях, поле «Максимальна сума замовлення».
Вона показується тільки для замовлень по Україні: накладний платіж —
послуга Нової Пошти, і за кордон вона його не возить. Тому картка має
бути ввімкнена обов'язково — без неї покупець із ЄС не матиме чим
заплатити.

**Банківський переказ** вимкнено навмисно. Він лежить у WooCommerce
з коробки; якщо колись знадобиться рахунок для юридичних осіб —
увімкнути й вписати реквізити, більше нічого не треба.

### Як замовлення стає оплаченим

Після оплати LiqPay лишається на **власній** сторінці «Дякуємо!» і
назад веде тільки кнопкою **«Повернутися на сайт»** — автоматичного
переходу немає. Це поведінка LiqPay, не сайту.

Дізнатись про оплату сайт може двома шляхами, і працюють обидва:

1. **Покупець повернувся.** Сторінка подяки сама питає LiqPay про
   статус — і показує «Смажимо й відправляємо» або «Оплата ще не
   підтверджена» з кнопками «Оплатити» й «Перевірити оплату». Це
   працює навіть на локальному сайті.
2. **Покупець не повернувся.** Тоді LiqPay сам стукає на
   `/wp-json/brix/v1/liqpay`. Цей шлях працює лише там, де сайт видно
   з інтернету, тобто на хостингу.

Тестова картка для sandbox: `4242 4242 4242 4242`, будь-який термін у
майбутньому, будь-який CVV, будь-яке ім'я.

## Крок 5. Перевірка перед показом

Пройди сам, як покупець:

- [ ] Каталог фільтрується, сортується, гортається
- [ ] У полі «Місто» на checkout зʼявляються підказки, а в «Адреса або
      відділення» — список відділень обраного міста
- [ ] Замовлення оформлюється й лист приходить
- [ ] Тестова оплата LiqPay проходить, після «Повернутися на сайт»
      видно «Смажимо й відправляємо», замовлення — «Обробляється»
- [ ] Перемикач «₴ / €» міняє ціни, а в євро накладного платежу немає
- [ ] Посилання «політика конфіденційності» під кнопкою замовлення
      відкриває сторінку, а не 404
- [ ] Без галочки «Я погоджуюсь з умовами продажу» замовлення не
      проходить, посилання веде на `/terms/`
- [ ] `https://brix.zapolskyi.com/?author=1` — 404, `/xmlrpc.php` — 403
- [ ] Підписка в підвалі: після «Підписатись» видно «Майже готово»,
      приходить лист, кнопка в ньому показує «Підписку підтверджено»
- [ ] На вкладці браузера — іконка «B°», а не логотип WordPress
- [ ] Кабінет: реєстрація поштою → лист «Задати пароль» → після пароля
      в кабінеті видно й замовлення, зроблені раніше гостем
- [ ] Підписка BRIX Club гостем: на checkout пояснення, що буде
      створено кабінет, а після замовлення підписка є в «Моя кава»
- [ ] Те саме англійською, під `/en/`
- [ ] Квіз доходить до результату з трьома лотами
- [ ] Кабінет показує замовлення, підписку й профіль смаку

І окремо: **вимкни JavaScript у браузері й повтори покупку.** Це
головне, що відрізняє цей проєкт — має працювати все.

## Демо-доступи

Створює команда `wp brix demo`:

| Логін | Пошта | Що показує |
|---|---|---|
| `demo` | `demo@brix.local` | замовлення, підписку BRIX Club, профіль смаку |
| `demo-b2b` | `b2b@brix.local` | оптові ціни −25%, мінімум 5 кг |

**Паролі задай сам** через **Користувачі** в адмінці. Команда ставить
випадкові й нікуди їх не виводить — демо-акаунт із відомим паролем у
репозиторії це запрошення зайти під ним.

Пошти навмисно на неіснуючому домені: на демо-стенді ці акаунти
отримуватимуть листи про замовлення.
