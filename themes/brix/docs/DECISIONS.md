## 1. Один репозиторій над `wp-content`, а не окремо тема й плагін

**Дата:** 16.09.2026 · **Фаза:** 0

ТЗ вимагає і власну тему `brix`, і окремий плагін `brix-core`. У попередніх
проєктах (TORQ, Площина) git лежав у корені теми, бо тема була всім проєктом.
Тут так не вийде: половина логіки за задумом живе в плагіні.

**Рішення.** Git-корінь — `app/public/wp-content/`. `.gitignore` спершу
ігнорує все (`/*`), потім точково повертає `themes/brix/` і `plugins/brix-core/`.
Ядро WordPress, WooCommerce, аплоади й кеш у репозиторій не потрапляють.

**Альтернативи.**
- *Два репозиторії.* Два посилання в портфоліо і ручна синхронізація версій
  теми й плагіна, які змінюються одним і тим самим комітом.
- *Код плагіна всередині теми.* Суперечить меті кейсу — показати саме
  розділення презентації та бізнес-логіки.

**Наслідки.** Один `git log` на весь проєкт. README лежить у корені репо,
а не в темі. Архів для хостингу збирається окремо для теми й для плагіна.

## 2. Збірка на `sass` CLI, а не Vite

**Дата:** 16.09.2026 · **Фаза:** 0

ТЗ називало Vite. На TORQ перевірено простішу схему і вона вижила
до продакшену.

**Рішення.** `npm run css` компілює `assets/scss/main.scss` →
`assets/css/main.css`. **Скомпільований CSS комітиться в репозиторій.**
JS — ванільні файли без бандлера, підключаються там, де потрібні.

**Чому.** Тема має працювати на хостингу без Node. Заливаєш архів — сайт
живий. З Vite будь-який деплой вимагає кроку збірки, а забутий
`npm run build` дає сайт без стилів.

**Альтернатива.** Vite з `dist/` у `.gitignore` і збіркою в GitHub Actions.
Це правильно для застосунку, але надлишково для теми з одним CSS-файлом
і кількома скриптами.

**Наслідки.** У дифах з'являється скомпільований CSS — його не рев'ювимо,
дивимось лише на `.scss`. Hot reload немає, є `npm run css:watch`.
Мінімізація й критичний CSS — окремими скриптами в `npm run build`.

## 3. Макети поза репозиторієм

**Дата:** 16.09.2026 · **Фаза:** 0

`design-source/` — 21 артборд, preview-сторінки й генератор на Node,
разом ~6 МБ. Це джерело дизайну, а не частина теми.

**Рішення.** Лежить локально в `themes/brix/docs/design-source/`,
додано в `.gitignore`. Усе, що з макетів потрібне продакшену, переноситься
в код: токени — в `assets/scss/abstracts/_tokens.scss`, компоненти —
в `assets/scss/components/`. Карта макетів, щоб не відкривати їх щоразу, —
в `03-makety.md`, і вона в репозиторії.

**Наслідки.** Репо лишається легким, в архів теми не потрапляє зайве.
Мінус — макети не видно на GitHub; це закриється скріншотами в README
на фазі 8.
